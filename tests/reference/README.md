# Testing the Python port against EMPOWER-1.0

Expected values in `tests/fixtures/empower/` are generated by executing the
original R implementation, independently of the Python model. They are stored
in the repository, so routine tests need neither R nor network access.

The reference configuration is also generated from the original input files.
Changing your experiment's root `config.toml` does not change the test case.
The Python solver and production model are not modified by these tests.

## Run the checks

From the repository root, with development dependencies installed:

```bash
# Quick reference checks
uv run pytest tests/ -m "empower and not slow" -q

# All reference checks, including both five-year simulations
uv run pytest tests/ -m empower -q

# Full project suite, including the reference checks
uv run pytest tests/ --maxfail=1 -q
```

`python -m pytest` is equivalent when using the installed project environment.
The `slow` marker is only a filter: no tests are skipped by default.

## Coverage and tolerances

| Check | Coverage | Acceptance |
| --- | --- | --- |
| Station input table | All 104 monthly values | Exact equality |
| Daily forcing | All four stations: MLD, SST, deep nutrient, day length, noon PAR | `rtol=1e-10`, `atol=1e-10` |
| Numerical light integration | 120 cases covering both irradiance shapes and both P–I curves | `rtol=1e-10`, `atol=1e-10` |
| EP85 and Anderson light integration | 30 cases for each method | `rtol=1e-10`, `atol=1e-10` |
| Chlorophyll absorption | 36 depth/chlorophyll cases | `rtol=1e-10`, `atol=1e-10` |
| Full ecosystem equations | 1,448 cases across all light, attenuation, and grazing choices | `rtol=1e-10`, `atol=1e-10` |
| Five-year BIOTRANS, original RK4 stepping | All 1,826 daily P–N–Z–D states | `rtol=1e-9`, `atol=1e-9` |
| Five-year BIOTRANS, production adaptive solver | All 1,825 common daily P–N–Z–D states | Absolute error ≤ 0.005 mmol N m⁻³ |

The ecosystem cases include shallow and deep mixed layers, both layer
boundaries, deepening and shoaling, two seasons, and low/zero concentrations.
Additional cases exercise temperatures of 0 and 25 °C. Rate-test failures show
the input row that failed. The fast checks compare equations to rounding-level
tolerance; they do not rely on a loose whole-simulation tolerance.

The R program freezes forcing during each four-stage RK4 update. A test-only
driver reproduces that schedule using the Python `ode` method. The separate
production test calls `NPZDModel.run()` with its normal adaptive solver. Its
0.005 absolute tolerance accommodates the observed numerical differences
(maximum about 0.0038), while the strict equation checks protect against
changes hidden by that tolerance. Python omits the final output endpoint, so
that test compares only times present in both outputs.

The existing `test_model_forcing.py` and `test_remote_forcing.py` cover Python's
remote-forcing extensions, including entrainment and cache separation. Those
extensions have no equivalent in the original R code. The reference tests
check agreement with the published approximations, not their physical accuracy
outside the tested inputs or agreement with observations.

## Regenerate the reference outputs

Source: Anderson, T. R., Gentleman, W. C., and Yool, A. (2015),
[EMPOWER-1.0](https://doi.org/10.5194/gmd-8-2231-2015), GMD 8, 2231–2262.
Use the [official supplementary archive](https://gmd.copernicus.org/articles/8/2231/2015/gmd-8-2231-2015-supplement.zip).
Its SHA-256 is:

```text
733c54529e357cb5d5561b9dc95d5880a00b39d4bcc7e2224f3662a8a2eb990f
```

Only regeneration requires `Rscript`; base R is sufficient. The checked-in
outputs were generated with R 4.6.1. With the archive downloaded earlier:

```bash
uv run python tests/reference/generate.py
```

For an archive stored elsewhere, or to review fresh outputs before replacing
the checked-in fixtures:

```bash
uv run python tests/reference/generate.py \
  --archive /path/to/gmd-8-2231-2015-supplement.zip \
  --output /tmp/empower-reference
```

The generator verifies the archive checksum before executing code. It extracts
the four source/input files into a temporary directory and runs `generate.R`.
That driver evaluates sections of the unmodified `EMPOWER1.r`: functions,
initialization, station interpolation, and the original five-year RK4 loop.
It skips the workspace-clearing command, rounded text output, and plotting.
The fixed line ranges apply only to the checksum-pinned 2015 supplement.
Fixtures are copied to the destination only after R completes successfully.

The CSV files record R's unrounded in-memory values at the precision supported
by its CSV writer. The generator does not import or call the Python port.
Review fixture changes against the original code; do not update expected
values merely to make a failing port test pass.
